# Crate: `auth`

**Tier:** 3 - App modules

**Depends on:** `ante`, `cosmos-types`, `kvstore`

**Consumed by:** M4 `bank`, M4 integration, later app/runtime crates

## Purpose

Implement the consensus-critical `x/auth` account store used by Celestia
app-v6. The keeper owns base-account persistence, account-number allocation,
and the account read/write adapter consumed by the M3 ante handler.

## Public API

- `BaseAccount`: address, optional public key, account number, and sequence.
- `ModuleAccount`: embedded base account, module name, and permissions.
- `Keeper::get_account`, `has_account`, `set_account`, `remove_account`, and
  `all_accounts`.
- `Keeper::get_module_account` and `set_module_account`.
- `Keeper::peek_next_account_number`, `next_account_number`, and
  `create_account`.
- `ante::AccountReader` and `ante::AccountWriter` implementations.
- `STORE_KEY` and `BASE_ACCOUNT_TYPE_URL` compatibility constants.

## Behavioral Requirements

### AUTH-REQ-1: Account collection encoding

- The mounted store name is `acc`.
- Account keys are the SDK collections prefix byte `0x01` followed by the raw
  20-byte account address.
- Base-account values are a protobuf `Any` with type URL
  `/cosmos.auth.v1beta1.BaseAccount`; its value is the protobuf `BaseAccount`.
- The address inside `BaseAccount` uses the `celestia` bech32 prefix and must
  match the raw address in the store key.
- Module accounts use `/cosmos.auth.v1beta1.ModuleAccount`, preserve their
  wrapper across sequence updates, and require an address derived from the
  module name. Unsupported account interface variants return a typed error.
- The unique account-number index uses the `accountNumber` prefix followed by
  an eight-byte big-endian account number and stores the raw account address.

### AUTH-REQ-2: Account-number allocation

- The global account-number sequence lives at key `0x02` as an eight-byte
  big-endian unsigned integer.
- A missing sequence starts at zero.
- `next_account_number` returns the current value and persists current + 1.
- Overflow and malformed stored values return typed errors.

### AUTH-REQ-3: Keeper behavior

- Creating an account allocates exactly one account number and persists a
  zero-sequence account without a public key.
- Creating an existing address fails without consuming an account number.
- Iteration is lexicographic by raw address.
- Sequence and public-key mutations preserve every other account field.
- Missing-account mutations fail and do not create implicit accounts.

### AUTH-REQ-4: Ante integration

- The keeper implements the M3 `AccountReader` and `AccountWriter` traits.
- Stored account values map losslessly into `ante::Account`.
- Keeper/storage failures cross the trait boundary as `ante::Error::State`.

## Conformance Fixtures

`fixturegen auth-accounts` uses Cosmos SDK v0.50.10 collections, auth types,
and interface codecs to emit:

- account collection keys and interface-wrapped values for accounts with and
  without public keys, including large counters;
- module-account values and indexes for the fee collector and both staking
  pools;
- the global account-number key and value encoding.

The committed fixture is `conformance/fixtures/auth/accounts.json` with a
metadata sidecar and is regenerated by:

```bash
cargo xtask refresh-fixtures --crate-name auth
```
