# ADR 0007: target celestia-app v10.5.0

Date: 2026-10-23. Status: accepted (owner's network/version target).

## Target and evidence

Target Mainnet's v10.5.0 and Mocha's v10.5.0-mocha, retaining v9.0.8 for
historical replay and the v9 → v10 transition. Read-only `abci_info` returned
10.5.0 at Mainnet height 15,221,231 (`rpc.celestia.pops.one`) and
10.5.0-mocha at Mocha height 1,951,411 (`rpc.celestia-mocha.com`). These
observations describe those endpoints, not every network operator.

The v10.5.0 and v10.5.0-mocha source trees are identical. Compared with
v10.4.0, the only replaced Go dependency that changes is hyperlane-cosmos
v1.3.0 → v1.3.1. celestia-core remains v0.42.3; cosmos-sdk remains
v0.52.12. The app version remains 10: these fixes do not require a new
store migration or a patch-version switch inside the Rust state machine.

## Ported behavior

* PrepareProposal branches normal/blob ante execution per transaction.
  Rejection discards partial writes and the replacement tx gas meter;
  success writes the branch and preserves the tx meter. The v9 proposal
  path retains its historical in-place behavior. ProcessProposal and
  FinalizeBlock are unchanged by this fix.
* PrepareProposal drops non-BlobTx payments for blobs and validates wrapped
  blob commitments/shapes before admitting them to the square. It can no
  longer propose these known-invalid transactions to its own
  ProcessProposal handler.
* Hyperlane verification walks routing ISMs iteratively. Repeated routes
  fast-forward whole gas-charge cycles, then replay the final cycle's
  individual charges. This preserves finite-meter gas consumption and the
  exact out-of-gas location. Infinite-meter cycles return hyperlane/4;
  VerifyDryRun rejects explicit limits above 10,000,000 before decoding
  the message, as v1.3.1 does.

The Go multiplexer fixes initialize its next app version and recover a
committed upgrade when Comet's state still has the old version. Rust has
one application process; it loads the app version from committed
consensus parameters and mounts upgrade stores on reopening. It has no
embedded-binary selection or next-app-version variable to port.

The remaining changes are to the separate Go fibre upload/storage server
and client (health, readiness, pruning, detached uploads, connection
timeouts), and test-network peer configuration. They do not change the
consensus node's x/fibre state transitions or wire protocol. This decision
does not add a fibre data-plane server to celestia-rs.

## Verification and ongoing gates

Active v10 Go oracle modules and devnet/CI builds use v10.5.0 and
hyperlane-cosmos v1.3.1; binary cache keys change with the target. Old
committed fixtures retain their recorded version metadata. New fixtures
are generated and rechecked by `conformance/fuzzoracle/v10` tests:

```sh
cd conformance/fuzzoracle/v10
go test .
# Explicit regeneration after reviewing a reference release:
UPDATE_PROPOSAL_VECTORS=1 UPDATE_ROUTING_VECTORS=1 go test .
```

`proposal-v10.5.json` records InitChain, FinalizeBlock, Commit, and proposal
responses. It includes rejected normal/blob ante runs followed by a valid
transaction whose fee cannot be paid twice, bare PFBs, and mismatched
blobs; each resulting proposal must pass Go's ProcessProposal.
`hyperlane-routing.json` records the exact raw ISM store entries and 110
verification cases: leaves, routing chains, self/two/three-node cycles,
tails into cycles, missing routes/ISMs, wrong types, finite gas boundaries,
huge limits and infinite meters. Rust compares results, error codes, gas
consumed and out-of-gas descriptors against these fixtures in workspace
tests; CI also reproduces them with Go.

Passing these regressions does not close C1 or F1. The release commit
still needs the recorded soak, campaign, nightly saturation,
cross-architecture determinism, mainnet replay and independent-review
evidence listed in MILESTONES.md. Public production recommendation remains
gated on those results.
