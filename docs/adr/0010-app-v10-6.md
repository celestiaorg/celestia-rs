# ADR 0010: target celestia-app v10.6.0

Date: 2026-11-07. Status: accepted. Supersedes ADR 0007 for new v10
qualification; its v10.5.0 evidence remains historical.

## Decision

Use celestia-app v10.6.0 as the current Go application oracle, with
celestia-core v0.42.8 and hyperlane-cosmos v1.3.3. Retain celestia-app
v9.0.8 as the historical replay and v9-to-v10 oracle. Build the v10.6.0
oracle with the release's Go 1.26.10 toolchain and record the compiler,
module closure and binary digest with qualification evidence.

The official v10.6.0 tag resolves to
`25f09cab3f8912bbe78c62909e8d39d8fa8b3fc0`. The locally pinned Linux
x86-64 oracle has SHA-256
`5545cd1926516fb2580403f5ab485ad35818756e285b37f321cf9f25870d5a37`.
These identifiers authenticate the reference used by the new campaign;
they do not make older evidence current.

## Compatibility boundary

App version remains 10, so the Rust state machine cannot select v10.5.0
or v10.6.0 semantics from `ConsensusParams.Version.App`. Current v10
execution therefore follows v10.6.0. In particular, hyperlane-cosmos
v1.3.3 accepts Ethereum signature recovery wire IDs 27 and 28 only.
Historical app version 9 keeps v1.1 behavior, including the CGO recovery
path's acceptance of specially constructed IDs 29 and 30.

New differential and qualification runs use v10.6.0. Stored v10.5.0
fixtures and reports keep their original labels and remain useful as
historical evidence. They are not relabeled or counted toward an exact
v10.6.0 release-candidate gate. Their live-devnet generator sources remain
byte-for-byte stable because the receipts authenticate those files; new
v10.6.0 runs pass the target versions explicitly and record separate evidence.

The node's reported `COMPATIBILITY_VERSION` and core compatibility string
remain at 10.5.0 / 0.42.3 until every audited v10.6.0 / v0.42.8 delta is
implemented and the full target-change batch passes qualification. The
reference-oracle retarget does not by itself assert completed compatibility.

## Network observation and qualification

Read-only public RPC observations on 2026-11-07 reported a heterogeneous
mainnet rollout: sampled endpoints returned v10.4.0, v10.5.0 and v10.6.0
at nearby heights. This establishes endpoint heterogeneity, not a uniform
network version or fresh provenance for every operator. The release target
comes from the official tag and release metadata; production recommendation
still requires exact-candidate campaigns and the observation windows in
ADR 0009.

The dependency update also includes consensus and node behavior beyond the
Hyperlane recovery rule. Source review and renewed differentials cover those
deltas separately. A focused or sample pass is not production-readiness
evidence.
