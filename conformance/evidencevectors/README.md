# evidence vectors

Scenarios for the Rust `evidence` crate generated by celestia-core v0.42.3
`evidence/`: duplicate-vote evidence (valid, wrong chain / round / type /
validator / height, identical block IDs, power mismatches, bad signatures,
time mismatch, missing header or validator set, expiry by blocks and/or
time) and light client attack evidence (lunatic, forward lunatic,
equivocation, amnesia, insufficient or wrongly reported byzantine
validators, bad conflicting signatures, missing commits, expiry). Each case
records the decoded evidence's `EvidenceFromProto` error, Go's
`Pool.CheckEvidence` outcome against mock stores, the pure
`VerifyDuplicateVote` / `VerifyLightClientAttack` results and the derived
byzantine validators, plus the decoded evidence's cmtjson form (as `/block`
renders it) and its `ABCI()` misbehaviors. Checked by
`crates/tier-4-runtime/evidence/tests/go_vectors.rs`,
`crates/tier-4-runtime/light/src/http.rs` (JSON decoding) and
`crates/tier-4-runtime/rpc/tests/evidence_json.rs` (JSON encoding).

```bash
cd conformance/evidencevectors
GOPATH=/tmp/claude-0/gopath GOFLAGS=-mod=mod GOTOOLCHAIN=go1.26.6 go run . -out ../fixtures/evidence/vectors.json
```

Evidence is always verified after a protobuf round trip, as a node only
sees decoded evidence; Go then reports an amnesia attack (no derivable
byzantine validators) as invalid.
